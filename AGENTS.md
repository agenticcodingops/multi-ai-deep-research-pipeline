# Agent instructions

## Commit and PR authorship policy (MANDATORY)

This repository is public; commit metadata is permanent and world-readable.
This file applies to **every** coding agent and contributor, regardless of
vendor.

The purpose of the policy is that no AI vendor, tool or model ever appears as a
contributor to this project.

**Contributors:** no AI assistant (for example Claude, Codex or ChatGPT,
Copilot, Cursor, Gemini, Grok, Antigravity, Jules, Kiro, Devin, Aider, or a
model such as Opus, Sonnet, Haiku or GPT-n) may be a commit author, a committer,
or a `Co-authored-by:` co-author. Commit an assistant's work under your own
configured git identity, and never add a `Co-authored-by:` trailer naming an
AI assistant. GitHub lists every co-author of a default-branch commit as a
contributor.

Any other identity may appear: humans, code-quality bots (for example
CodeRabbit, Semgrep, SonarCloud), Dependabot, release bots and workflow bots.
A `Signed-off-by:` line is not contributor credit and is allowed.

**PR and issue text:** PR descriptions, issue bodies and comments carry no AI
attribution line: no `Co-authored-by:` line naming an AI assistant, and no
`Generated with <AI assistant>` or `Generated by <AI assistant>` byline.

Everything else is fine. Tool, vendor and model names may appear in commit
subjects and bodies, branch names, tag messages, PR titles, PR bodies, review
summaries and files.

Write commit messages in the imperative mood, describing the change.

Do not write `@` followed by a bot's login in a PR description, issue or
comment unless you mean to start that bot: a mention can start a cloud task.

### Enforcement

| Layer | File | Bypassable? |
|---|---|---|
| Attribution disabled at source | `.claude/settings.json` | n/a |
| Local commit check | `.githooks/commit-msg` | `--no-verify` |
| Local push check | `.githooks/pre-push` | `--no-verify` |
| **Server-side CI** | `.github/workflows/commit-hygiene.yml` | Not by `--no-verify`, but see below |

The hooks and CI check only the rules above: the author, committer and
`Co-authored-by` identities of each commit against a deny list of AI
assistants in `.githooks/branding-guard.sh`, and the PR body for AI
attribution lines. The deny list does not know every assistant; the policy
applies whether or not a check catches it. Issue bodies and comments are
covered by the policy, not by a check: no hook or workflow scans them.

The CI check is not a merge gate. `master` has no branch protection, so a direct
push lands before CI runs, and CI then only reports the failure. CI also runs
the guard from the commit under test, so a change to `.githooks/` is reviewed
like any other code change. `tests/test_branding_guard.py` tests the guard and
the hooks, and CI runs it first.

Enable the local hooks once per clone:

```sh
sh .githooks/install.sh
```

**Never use `git commit --no-verify` or `git push --no-verify`, and never edit
or disable the hooks to get a commit through.** If a hook blocks you, remove
the AI co-author trailer, or re-commit under your own identity. Server-side CI
enforces the same rule and will fail the build.
